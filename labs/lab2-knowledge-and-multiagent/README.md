# Lab 2: ナレッジとマルチエージェント

> Lab 1 で作ったエージェントに社内文書をナレッジとして追加し、回答の変化を確認します。さらに、受付役が専門エージェントへ振り分ける **マルチエージェント構成** を組み立てます。

セットアップ・演習の流れは [ルート README](../../README.md) を参照してください。

---

> ❗ **前提**: [Lab 1](../lab1-foundry-basics/README.md) が完了し、「相談室アシスタント v1」が作成済みであること。

## 🎯 このパートのゴール

- エージェントに **ナレッジ（File Search）** を追加し、回答が根拠を持つようになることを確認する
- 回答に **引用元** が表示される仕組みを理解する
- ナレッジの品質が回答の品質を決めることを、**実際の矛盾** を通じて体感する
- **Code Interpreter** でデータを集計・可視化させる
- **Connected Agents** で、受付役が専門エージェントに振り分ける構成を作る

## 演習 1: ナレッジを追加する (20min)

### 1.1 配布ファイルを確認する

#### 手順

1. 当日配布された `knowledge` フォルダをデスクトップなどに展開する
2. 上の表の 9 ファイルが揃っていることを確認する

**✅ 成功確認:**
- Word 5 ファイル、PDF 3 ファイル、CSV 1 ファイルが揃っている

### 1.2 ナレッジを追加する

#### 手順

1. Foundry ポータルで **「エージェント」** を開き、**「相談室アシスタント v1」** を選択する
2. 設定パネルを下にスクロールし、**「ナレッジ」** (Knowledge) セクションの **「+ 追加」** をクリック
3. 表示された一覧から **「ファイル」** (Files) を選択する
4. **「ローカル ファイルをアップロードする」** を選び、次の **8 ファイル** をまとめて選択する

```
製品FAQ_アクアクリア.docx
製品FAQ_キュットフォーム.docx
製品FAQ_モイストヴェール.docx
製品仕様シート_アクアクリア.pdf
製品仕様シート_キュットフォーム.pdf
製品仕様シート_モイストヴェール.pdf
対応マニュアル.docx
社内ルール.docx
```

5. ベクターストア名に `sunlight-cs-knowledge` と入力する
6. **「アップロードして保存」** をクリックし、処理の完了を待つ（1〜2 分）

> ⚠️ **`問い合わせ履歴.csv` はここでは追加しません。** このファイルは演習 3 で Code Interpreter に使います。文書検索用のナレッジとは扱いが異なります。

**✅ 成功確認:**
- ナレッジ セクションに **「ファイル検索」** (File search) が表示される
- ベクターストア `sunlight-cs-knowledge` に **8 ファイル** が登録されている
- 各ファイルのステータスが **「完了」** になっている

> 💡 **File Search とは**: アップロードした文書を自動的に分割・ベクトル化し、質問に関連する箇所だけを検索して回答に使う仕組みです。全文をモデルに渡すわけではないため、大量の文書でも動作します。

### 1.3 同じ質問をもう一度投げる

Lab 1 の演習 1.2 と **まったく同じ質問** を投げて、違いを確認します。

#### 手順

1. **「プレイグラウンドで試す」** をクリック
2. 次の質問を送信する

```
アクアクリアは、ドラム式洗濯機でも使えますか？
```

**✅ 期待される挙動:**
- 具体的な根拠（適合表の内容）を含んだ回答が返る
- 回答の下部または文中に **引用元のファイル名** が表示される
- Instructions のルールどおり、3 行以内かつ資料名付きで返る

> 💡 **引用をクリックしてみてください**: 引用元の表示をクリックすると、どの文書のどの箇所を根拠にしたかを確認できます。「AI がそう言っている」ではなく「この資料にこう書いてある」と言えることが、業務利用では決定的に重要です。

## 演習 2: ナレッジの質が、回答の質を決める (10min)

> ⚠️ **この演習が本日のハイライトです。** 手を動かすより、起きたことの意味を考える時間にしてください。

### 2.1 保管温度を聞いてみる

#### 手順

1. プレイグラウンドで次の質問を送信する

```
製品の保管温度の範囲を教えてください。
```

2. 返ってきた答えを控える
3. **新しい会話を開始**（画面上部の「+ 新しいチャット」）し、**同じ質問をもう一度**送信する

**✅ 観察してほしいこと:**
- 1 回目と 2 回目で、答えが変わることがある
- あるいは、複数の値が並記される
- あるいは、片方だけが断定的に返る

### 2.2 詰め替え後の使用期限を聞いてみる

#### 手順

```
詰め替えた後、どのくらいで使い切ればいいですか？
```

**✅ 観察してほしいこと:**
- 演習 2.1 と同様に、答えが安定しない

### 2.3 何が起きているかを確認する

配布したナレッジには、**意図的に矛盾が仕込んであります。**

| 項目 | 製品FAQ（Word） | 製品仕様シート（PDF） |
|------|------|---------|
| 保管温度 | 0℃〜40℃ | 5℃〜35℃ |
| 詰め替え後の使用目安 | 6か月以内 | 3か月以内 |

#### 手順

1. 配布ファイルの `製品FAQ_アクアクリア.docx` を開き、保管に関する記載を探す
2. `製品仕様シート_アクアクリア.pdf` を開き、保管条件の記載を探す
3. 両者が食い違っていることを自分の目で確認する

**✅ 成功確認:**
- 2 つの文書で、同じ項目に異なる値が書かれていることを確認できた

**ポイント解説:**

- エージェントは **どちらも「正しい社内文書」として扱います**。どちらが新しいか、どちらが正本かを判断する材料を持っていません
- したがって、**回答が揺れるのはモデルの性能問題ではありません**
- 実務では、次のような理由でこの状態が日常的に起きます
  - 部署ごとに文書を管理している
  - 改訂が片方にだけ反映された
  - 旧版が共有フォルダに残っている

> ⚠️ **持ち帰っていただきたい結論**
>
> **これは AI の精度の問題ではなく、ナレッジ側の版管理・整備の問題です。**
> エージェント導入の成否は、モデル選定よりも「何を読ませるか」の整備で決まります。

### 2.4 書式のばらつきも見てみる（任意）

3 つの FAQ は、それぞれ作成部署が異なる設定で、書式もバラバラです。

| ファイル | 設定上の作成部署 | 書式 |
|------|------|---------|
| `製品FAQ_アクアクリア.docx` | ホームケア部 | 3 列の表（台帳形式）、文書番号あり |
| `製品FAQ_キュットフォーム.docx` | キッチンケア部 | 章立ての読み物形式、文書番号なし |
| `製品FAQ_モイストヴェール.docx` | ビューティケア部 | Q. / A. のプレーン段落 |

次の質問を投げると、複数ファイルを横断して情報を集められるかが分かります。

```
3ブランドすべての詰め替え容量を、表にまとめてください。
```

> 💡 **書式が揃っていなくても読めます**: File Search は書式の違いに比較的強く、台帳でも読み物でも情報を拾えます。**問題は書式ではなく、内容の矛盾のほうです。**

## 演習 3: データを分析させる (15min)

文書検索だけでなく、**データを計算させる** こともできます。

### 3.1 Code Interpreter を有効にする

#### 手順

1. エージェント設定パネルの **「アクション」** (Actions) セクションで **「+ 追加」** をクリック
2. **「コード インタープリター」** (Code interpreter) を選択する
3. **「ファイルを追加」** から `問い合わせ履歴.csv` をアップロードする
4. **「保存」** をクリック

**✅ 成功確認:**
- アクション セクションに **「コード インタープリター」** が表示される
- 添付ファイルに `問い合わせ履歴.csv` が登録されている

> 💡 **Code Interpreter とは**: エージェントが Python コードを書いて実行できるツールです。集計・グラフ作成・ファイル変換などを、その場で処理します。実行環境はサンドボックス化されており、外部には接続しません。

### 3.2 集計させてみる

#### 手順

次の質問を順に送信します。

```
問い合わせ履歴から、月別の件数を集計してください。
```

```
2026年7月に問い合わせが急増しています。何が起きたか教えてください。
```

```
月別の問い合わせ件数を棒グラフにしてください。
```

**✅ 期待される挙動:**

| 質問 | 期待される回答 |
|------|---------|
| 月別集計 | 4月30件、5月29件、6月29件、**7月50件**、8月31件、9月31件 |
| 7月の急増理由 | 7月50件のうち **25件がキュットフォームの品質・不具合（ポンプ関連）** に集中している |
| 棒グラフ | 画像が生成され、7月に明確な山が見える |

> 💡 **生成されたコードを見てください**: 回答の横にある展開ボタンから、エージェントが書いた Python コードを確認できます。**どう計算したかが検証できる**ため、数字の根拠を説明できます。

### 3.3 さらに踏み込む（任意）

```

```

## 演習 4: マルチエージェントを組む (20min)

ここまでは 1 体のエージェントに全部やらせてきました。実務では、**役割ごとに分けた方が精度も保守性も上がります。**

### 4.1 完成形を確認する

これから、次の構成を作ります。

```
            受付エージェント（オーケストレーター）
                        │
      ┌─────────────────┼─────────────────┐
      │                 │                 │
  FAQ回答            履歴分析            起案
  エージェント        エージェント        エージェント
  Knowledge:         Tool:              Instructions:
  FAQ・仕様シート     Code Interpreter    エスカレーション
  対応マニュアル       問い合わせ履歴       報告文の下書き
  社内ルール          200件
```

質問の種類を受付が判断し、適切な担当に渡します。

### 4.2 FAQ回答エージェントを用意する

すでに作ってある「相談室アシスタント v1」を、そのまま FAQ 担当として使います。

#### 手順

1. エージェント一覧で **「相談室アシスタント v1」** を開く
2. エージェント名を次のように変更する

```
FAQ回答エージェント
```

3. **「アクション」** から **コード インタープリター を削除**する（履歴分析は別エージェントに任せるため）

**✅ 成功確認:**
- 名前が「FAQ回答エージェント」になっている
- ナレッジ（File Search）は残っている
- アクションにコード インタープリターがない

### 4.3 履歴分析エージェントを作る

#### 手順

1. **「エージェント」** → **「+ 新しいエージェント」** をクリック
2. 次のように設定する

| 項目 | 値 |
|------|------|
| エージェント名 | `履歴分析エージェント` |
| デプロイ | `gpt-5.4-mini` |

3. **Instructions** に次を貼り付ける

```text
あなたはサンライト株式会社 お客様相談室の問い合わせデータを分析するアナリストです。

- 添付された問い合わせ履歴データを使って、件数・傾向・相関を分析してください。
- 集計結果を先に示し、そのあとに解釈を述べてください。
- 件数や日数は必ず具体的な数値で示してください。
- データに含まれていない情報を推測して答えないでください。
- 重要度は1が軽微、4が最重要です。
```

4. **「アクション」** → **「コード インタープリター」** を追加し、`問い合わせ履歴.csv` をアップロードする
5. **「保存」** をクリック

**✅ 成功確認:**
- プレイグラウンドで「7月の件数は？」と聞くと、50 件と答える

### 4.4 起案エージェントを作る

#### 手順

1. **「+ 新しいエージェント」** をクリック
2. 次のように設定する

| 項目 | 値 |
|------|------|
| エージェント名 | `起案エージェント` |
| デプロイ | `gpt-5.4-mini` |

3. **Instructions** に次を貼り付ける

```text
あなたはサンライト株式会社 お客様相談室の記録・起案担当です。
オペレーターから受けた内容をもとに、関係部署へのエスカレーション報告文の下書きを作成します。

【報告文に必ず含める項目】
1. 件名
2. 受付日時（不明な場合は「YYYY-MM-DD」と記載）
3. お客様からの申し出内容（事実のみ）
4. 一次対応で確認した事項
5. エスカレーション理由と緊急度
6. 依頼事項

【ルール】
- 事実と推測を明確に分けて記述してください。
- 原因を断定する表現は使わないでください。
- お客様の個人情報は記載しないでください。
- 社内文書としての体裁を整えてください。
```

4. **「保存」** をクリック

**✅ 成功確認:**
- プレイグラウンドで「ポンプから液が出ないという申し出がありました。報告文を作ってください」と入力すると、6 項目を備えた下書きが返る

### 4.5 受付エージェントを作って接続する

#### 手順

1. **「+ 新しいエージェント」** をクリック
2. 次のように設定する

| 項目 | 値 |
|------|------|
| エージェント名 | `受付エージェント` |
| デプロイ | `gpt-5.6-sol` |

> 💡 **受付だけ上位モデルにします**: 振り分けの判断を誤ると全体が破綻するため、オーケストレーターには判断力の高いモデルを割り当てるのが定石です。

3. **Instructions** に次を貼り付ける

```text
あなたはサンライト株式会社 お客様相談室の受付担当です。
オペレーターからの相談内容を読み、適切な担当エージェントに取り次いでください。

【振り分けのルール】
- 製品の仕様・使い方・成分・安全性・社内手順に関する質問
  → FAQ回答エージェント に渡してください。
- 問い合わせの件数・傾向・期間比較など、データの集計や分析が必要な質問
  → 履歴分析エージェント に渡してください。
- 関係部署への報告文・エスカレーション文書の作成依頼
  → 起案エージェント に渡してください。

【回答のルール】
- 担当エージェントから受け取った内容を、オペレーターに分かりやすく伝えてください。
- どの担当が回答したかを、回答の冒頭に1行で示してください。
- 判断に迷う場合は、どの担当に渡すべきか確認してください。
```

4. **「エージェント」** (Connected agents) セクションの **「+ 追加」** をクリック
5. 次の 3 つを順に接続する

| 接続するエージェント | 名前 | 説明（いつ呼ぶか） |
|------|------|---------|
| FAQ回答エージェント | `faq_agent` | 製品の仕様・使い方・成分・安全性・社内手順に関する質問に答える |
| 履歴分析エージェント | `history_agent` | 問い合わせ履歴データの集計・傾向分析を行う |
| 起案エージェント | `draft_agent` | 関係部署へのエスカレーション報告文を作成する |

6. **「保存」** をクリック

> ⚠️ **「説明」欄が振り分け精度を決めます**: 受付エージェントは、この説明文を読んでどれを呼ぶか判断します。曖昧に書くと誤った振り分けが起きます。**「いつ呼ぶか」を具体的に書いてください。**

**✅ 成功確認:**
- 接続済みエージェント一覧に 3 件が表示される

### 4.6 振り分けをテストする

#### 手順

**受付エージェントのプレイグラウンド**で、次の 3 つを順に送信します。

```
詰め替えの保管期限は？
```

```
先月いちばん多かった問い合わせカテゴリは？
```

```
ポンプから液が出ないという申し出がありました。品質保証部にエスカレーションしたいので報告文を作ってください。
```

**✅ 期待される挙動:**

| 質問 | 振り分け先 | 応答の特徴 |
|------|------|---------|
| 詰め替えの保管期限 | FAQ回答エージェント | ナレッジを引用して回答 |
| 先月最多のカテゴリ | 履歴分析エージェント | 具体的な件数を示す |
| 報告文の作成 | 起案エージェント | 6 項目の下書きが返る |

> 💡 **うまく振り分かないときは**: 受付エージェントの Instructions と、接続時の「説明」欄を見直してください。**表現が抽象的だと迷います。** 「データの集計」「報告文の作成」のように、動詞を具体的に書くと安定します。

### 4.7 振り分けを崩してみる（任意）

意図的に誤動作させると、仕組みの理解が深まります。

**試してみる例:**

1. 接続した `history_agent` の **説明欄を空にする** → 集計質問が FAQ 担当に流れることがある
2. 受付の Instructions から **振り分けルールのブロックを削除する** → 判断が不安定になる
3. **どちらとも取れる質問** を投げてみる

```
7月に多かったポンプの不具合について、製品仕様も含めて教えてください。
```

> 💡 **3 の質問は、本来 2 つの担当にまたがります。** 受付がどう処理するかを観察してください。複数の担当を順に呼ぶ場合もあります。

## 🚨 トラブルシューティング

### ファイルのアップロードが「処理中」から進まない

**原因**: ファイルサイズが大きい、または同時アップロード数が多い。

**解決方法**:
1. 2〜3 分待つ（PDF は Word より時間がかかります）
2. 画面を再読み込み（F5）してステータスを確認する
3. それでも進まない場合は、ファイルを 2〜3 個ずつに分けてアップロードし直す

### 回答に引用元が表示されない

**原因**: ナレッジを参照せずに、モデルの一般知識だけで答えている。

**解決方法**:
1. 質問が具体的すぎないか確認する（「洗剤について教えて」では参照されにくい）
2. 製品名（アクアクリアなど）を含めて質問する
3. Instructions に次の 1 行を追加する

```text
回答は必ずナレッジの内容に基づいて行い、参照した資料名を明記してください。
```

### Code Interpreter が CSV を読めない

**原因**: 文字コードの問題、またはファイルがナレッジ側に登録されている。

**解決方法**:
1. `問い合わせ履歴.csv` が **「アクション」→「コード インタープリター」** に添付されているか確認する（ナレッジ側ではありません）
2. エージェントに次のように指示する

```
問い合わせ履歴.csv を UTF-8 として読み込んでから集計してください。
```

### 受付エージェントが振り分けず、自分で答えてしまう

**原因**: Instructions に振り分けの指示が弱い、または接続エージェントの説明が不足している。

**解決方法**:
1. 接続時の **「説明」** 欄が空になっていないか確認する
2. 受付の Instructions の末尾に次を追加する

```text
質問には自分で直接答えず、必ずいずれかの担当エージェントに取り次いでください。
```

### 接続エージェントの応答が返ってこない / 非常に遅い

**原因**: 連鎖的に複数のエージェントを呼んでいる、またはレート制限。

**解決方法**:
1. 1 分ほど待つ（3 体を順に呼ぶ場合、時間がかかります）
2. 接続エージェントの数を一時的に 1 つに減らして切り分ける
3. 受付のデプロイを `gpt-5.6-sol` から `gpt-5.4-mini` に変更して再試行する

### 「同じ質問なのに毎回答えが違う」

**原因**: 演習 2 で扱った **ナレッジの矛盾** が原因である可能性があります。

**解決方法**: これは不具合ではありません。演習 2.3 を読み返してください。実務では、参照する文書の正本を 1 つに絞ることで解消します。
